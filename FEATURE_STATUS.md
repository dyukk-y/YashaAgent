# Архив Telegram Business: реализовано и что осталось

Этот документ фиксирует текущие возможности YashaAgent и отличия от подхода `telegram-savemod-bot`. Это не обещание возможностей, которые Telegram Bot API не предоставляет.

## Уже реализовано в YashaAgent

- Архивирование сообщений, которые приходят боту через Telegram Business, когда подключение включено и выдано право чтения.
- История сохранённых изменений текста/подписи: старое и новое значение.
- Лента событий удаления. Telegram передаёт идентификаторы удалённых сообщений; если тело было сохранено ранее, архив показывает его, иначе отображается событие без исходного текста.
- Сохранение копий обычных вложений (фото, видео, GIF-анимации, документы, стикеры, голосовые, аудио и видеокружки) в отдельном каталоге на сервере; ошибки скачивания отмечаются в базе.
- Защищённое открытие/скачивание сохранённых вложений из Mini App, включая предпросмотр изображений; отдельные admin-маршруты позволяют главному администратору открывать файлы чужих архивов.
- Поиск, просмотр чатов, скрытие чатов для обычного пользователя и общий архив для главного администратора.
- Ограничение доступа к API по проверенной подписи Telegram Mini App; администраторские маршруты отдельно проверяют список ADMIN_USER_IDS.
- Уведомления об изменениях и удалениях, если они включены настройками на сервере.

## Ещё не реализовано

1. **Отдельная галерея медиа.** Вложения доступны из карточки сообщения, но нет общего фильтра по фото/видео/голосовым/документам и отдельной галереи.
2. **Встроенный просмотр видео и аудио.** Сейчас можно скачать файл; встроенный проигрыватель для видео/аудио и более богатые превью не добавлены.
3. **Медиа-группы (альбомы) как единый объект.** Сообщения с несколькими вложениями не собираются в удобный альбомный просмотр.
4. **Самоуничтожающиеся фото/видео.** Репозиторий-источник описывает сценарий с Telegram Premium и ответом на такое сообщение. Это нельзя считать обычной функцией Bot API: бот не получает произвольный доступ к содержимому самоуничтожающихся сообщений. Нельзя обещать их сохранение для всех пользователей и типов чатов.
5. **Надёжная политика хранения файлов.** Не реализованы лимит размера, квоты на пользователя, очистка старых файлов, статистика диска и настройка срока хранения.
6. **Проверки полноты архива.** Нет отдельного статуса «архивирование активно / нет доступа / есть ошибки скачивания» для каждого подключения и диагностики пропусков.
7. **Повторное получение старых вложений.** Медиа сохраняется только при обработке новых сообщений после обновления. Ранее сохранённые записи не могут автоматически получить копии файлов задним числом.

## Важные ограничения Telegram

- Бот не может запросить полную историю обычного чата задним числом.
- Событие удаления обычно содержит идентификаторы, а не исходный текст или файл. Если содержимое не было получено и сохранено до удаления, восстановить его из одного события невозможно.
- Доступ к Business-сообщениям зависит от активного Business-подключения и предоставленных прав.
- Сохранение медиа требует дополнительного дискового пространства и постоянного тома на хостинге. По умолчанию файлы пишутся в `/data/media`; на Bothost необходимо убедиться, что этот путь находится на постоянном диске/volume.

## Рекомендуемый следующий этап

- Добавить галерею и фильтры медиа, встроенный просмотр видео/аудио и объединение альбомов.
- Добавить лимиты, квоты и автоматическую очистку старых файлов до накопления большого архива.
- Добавить страницу состояния Business-подключения и диагностику ошибок скачивания.
- Отдельно изучить доступные Telegram API ограничения для самоуничтожающихся медиа, не обещая восстановление того, что Bot API не отдаёт.

Новые AI-функции для этой работы не нужны и в этом плане не предлагаются.
