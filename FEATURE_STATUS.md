# Архив Telegram Business: реализовано и что осталось

Этот документ фиксирует текущие возможности YashaAgent и отличия от подхода `telegram-savemod-bot`. Это не обещание возможностей, которые Telegram Bot API не предоставляет.

## Уже реализовано в YashaAgent

- Архивирование сообщений, которые приходят боту через Telegram Business, когда подключение включено и выдано право чтения.
- История сохранённых изменений текста/подписи: старое и новое значение.
- Лента событий удаления. Telegram передаёт идентификаторы удалённых сообщений; если тело было сохранено ранее, архив показывает его, иначе отображается событие без исходного текста.
- Метаданные типов вложений в архиве (фото, видео, документ, аудио, голосовое, стикер и другие).
- Поиск, просмотр чатов, скрытие чатов для обычного пользователя и общий архив для главного администратора.
- Ограничение доступа к API по проверенной подписи Telegram Mini App; администраторские маршруты отдельно проверяют список ADMIN_USER_IDS.
- Уведомления об изменениях и удалениях, если они включены настройками на сервере.

## Ещё не реализовано

1. **Физическое сохранение вложений.** Сейчас сохраняются данные сообщения и метаданные вложения, но само содержимое файла не загружается в постоянное хранилище и Mini App не предоставляет полноценное скачивание сохранённого файла.
2. **Просмотр/повторная отправка медиа из ленты удалений.** Если сообщение с вложением было удалено, в ленте можно увидеть событие и тип вложения, но нельзя гарантированно открыть сохранённую копию файла.
3. **Отдельная галерея медиа.** Нет фильтра по фото/видео/голосовым/документам, предпросмотра, скачивания и управления занимаемым местом.
4. **Медиа-группы (альбомы) как единый объект.** Сообщения с несколькими вложениями не собираются в удобный альбомный просмотр.
5. **Самоуничтожающиеся фото/видео.** Репозиторий-источник описывает сценарий с Telegram Premium и ответом на такое сообщение. Это нельзя считать обычной функцией Bot API: бот не получает произвольный доступ к содержимому самоуничтожающихся сообщений. Нельзя обещать их сохранение для всех пользователей и типов чатов.
6. **Надёжная политика хранения файлов.** Не реализованы лимит размера, квоты на пользователя, очистка старых файлов, статистика диска и настройка срока хранения.
7. **Проверки полноты архива.** Нет отдельного статуса «архивирование активно / нет доступа / есть ошибки скачивания» для каждого подключения и диагностики пропусков.

## Важные ограничения Telegram

- Бот не может запросить полную историю обычного чата задним числом.
- Событие удаления обычно содержит идентификаторы, а не исходный текст или файл. Если содержимое не было получено и сохранено до удаления, восстановить его из одного события невозможно.
- Доступ к Business-сообщениям зависит от активного Business-подключения и предоставленных прав.
- Сохранение медиа может потребовать дополнительного дискового пространства и постоянного тома на хостинге. Если файловое хранилище не сохраняется между перезапусками, копии будут потеряны.

## Рекомендуемый следующий этап

- Добавить загрузку обычных вложений при получении сообщения и хранить файлы в постоянном каталоге на сервере.
- Добавить защищённую выдачу/скачивание файлов через API Mini App с проверкой владельца или главного администратора.
- Показывать кнопки «Открыть» и «Скачать», превью изображений и видеороликов, а для аудио — встроенное воспроизведение там, где браузер поддерживает формат.
- Отображать статус сохранения каждого файла и понятную причину, если Telegram не позволил его скачать.
- Добавить лимиты, квоты и очистку старых файлов, прежде чем включать архивирование больших объёмов медиа.

Новые AI-функции для этой работы не нужны и в этом плане не предлагаются.
